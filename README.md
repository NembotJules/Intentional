## Running in Expo Go (Physical Device)

To run Intentional on your iPhone using Expo Go:

1. **Requirements:**
   - Node 20+ installed
   - Expo Go app installed on your iPhone ([App Store](https://apps.apple.com/app/expo-go/id982107779))
   - Same WiFi network for computer and phone (or good cellular connection for tunnel)

2. **Install dependencies:**
   ```bash
   cd intentional-expo
   npm install
   ```

3. **Start the development server:**
   ```bash
   npm run go
   ```
   This runs `expo start --tunnel` which creates a connection that works over the internet.

4. **Scan the QR code** with your iPhone camera and open in Expo Go.

**Important notes:**
- **SQLite works on device in Expo Go** — your goals, actions, and sessions are stored locally.
- **Web is a shim** — the app is optimized for native iOS/Android.
- **Notifications may prompt** for permission when you enable reminders.
- **App blocking (Family Controls) does not work in Expo Go** — it requires a native build with Apple's Screen Time entitlements. The Settings screen has a checkbox fallback to record your blocking preferences, and Focus sessions will show "Timer only" status when native blocking is unavailable.

## Strict mode (iOS dev build only)

Strict mode (US-077) blocks the apps the person picked when a habit's start time comes, for the habit's duration, **without Intentional being open**. It is on by default for every habit ("Block apps automatically" in the habit form). It only works in an iOS 16+ **development or production build**; in Expo Go, on the web and on Android the toggle is hidden and habits use the notification + one-tap flow (US-075/076).

**How it works**
- `services/appBlocking.syncHabitBlocks()` (run by `services/habitSync.syncHabits()`) registers one `DeviceActivitySchedule` per strict habit and weekday (one daily schedule for an every-day habit) through the local module `intentional-expo/modules/family-controls`.
- iOS runs the **DeviceActivityMonitor extension** (`intentional-expo/targets/device-activity-monitor`, generated by `@bacons/apple-targets` at prebuild) at the start and end of each window; it shields the picked apps in the `habit` ManagedSettings store and clears them at the end.
- The app and the extension share the App Group `group.com.intentional.app` (the app selection, the running window, "lifted today" markers).
- `appBlocking.endActiveHabitBlock(habitId)` lifts a running block ("Skip today", ending the session early) and keeps that habit unblocked for the rest of the day.
- Apple limits: at most 20 schedules per app (extra windows are skipped and the notification falls back to "Time to start…"), windows of at least 15 min.

**Build**
1. Apple Developer portal: register the App Group `group.com.intentional.app`, and enable **Family Controls** + **App Groups** for both `com.intentional.app` and `com.intentional.app.DeviceActivityMonitor` (EAS Build can sync capabilities for you).
2. Development builds work with the Family Controls (Development) capability. **TestFlight / App Store need the Family Controls distribution entitlement, which Apple must approve** ([request form](https://developer.apple.com/contact/request/family-controls-distribution)) for the app **and** the extension bundle id.
3. Set `ios.appleTeamId` in `app.json` (prebuild warns without it), then `cd intentional-expo && npx expo prebuild -p ios --clean` and `eas build --profile development --platform ios` (or open `ios/` in Xcode and run on a device; the simulator can't block apps).

**Test on a device**
1. Settings → pick the apps to block (allow Screen Time access when asked).
2. Add a habit with a start time 2–3 min from now on today's weekday, 15 min, "Block apps automatically" on. Lock the phone.
3. At the start time, open a picked app: it shows the Screen Time shield, without Intentional having been opened. After the duration it opens normally.
4. Repeat, then tap **Skip today** (or end the session early): the shield lifts at once and doesn't come back today.
5. Turn "Block apps automatically" off for the habit: next time, only the notification arrives.

## Setup (Xcode on macOS)

1. Open Xcode and create a new **App** project:
   - Product Name: `Intentional`
   - Team: your team
   - Organization Identifier: e.g. `com.yourname`
   - Interface: SwiftUI
   - Language: Swift
   - Storage: None (we use SwiftData manually)
   - Minimum Deployment: iOS 17.0

2. Delete the default `ContentView.swift` if Xcode created one.

3. Add all source files from this repo into the Xcode project:
   - Drag the `Intentional` folder (Models, Views, ViewModels, Resources, etc.) into the project navigator.
   - Ensure "Copy items if needed" is unchecked (they're already in place).
   - Create groups to match the folder structure.

4. Ensure the app target includes:
   - All `.swift` files under Intentional/
   - No duplicate or stray files.

5. **Family Controls (app blocking during focus):** To enable focus session app blocking, add the **Family Controls** capability in Xcode (Signing & Capabilities). The simulator does not support FamilyControls; test on a real device. On first "Start Focus" the system will prompt for Screen Time permission. To block specific app categories, implement a screen that uses `FamilyActivityPicker` and call `FocusLockService.shared.setSelection(selection)` with the result.

6. Build and run on simulator or device.
